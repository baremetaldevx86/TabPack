# a38-report-reference: agent report

## Summary

I implemented `get_reference_dir`, `extract_churn_reference` and `load_saved_reference`
in `src/tabpack_repro/reporting/reference.py`. I also generated
`results/reference/churn_official.json` from the official clone at commit
`05a89e21b955f12de84889d662e15ca534019aaa` and committed it.

The clone ships Churn reports for all four TabPack variants. Each variant has both a
main run and an evaluation run, which is the paper's conservative protocol. Nothing is
missing, so every variant has `evaluation_available: true`.

**Where "85.75 ± 0.14" comes from.** a45 quoted this number in `docs/EXPERIMENT.md`.
It comes from
`experiments/tabpack/churn/eval-online-ensembles/greedy/evaluation/report.json`. The
report has 5 seeds, and the number is the mean and sample std (`statistics.stdev`,
ddof = 1) of
`experiments[*].report.online_ensembles.greedy.report.metrics.test.score` over those
seeds. This is exactly the recipe in the official README ("Metrics"). The per-seed
scores are 0.8585, 0.858, 0.858, 0.855 and 0.858, which give a mean of 0.8575 and a
std of 0.001414.

The paper prints the same value. In arXiv:2607.05380v1, Appendix G, Table 14 (Churn
block), the TabPack row is 0.8575±0.0014. I fetched the arXiv HTML to check this. The
other three variants also match the paper to 4 decimals:

- TabPack†: 0.8623±0.0028
- TabPack†_MacBook: 0.8588±0.0052
- TabPack†_Offline: 0.8562±0.0048

One inconsistency: the caption of Table 14 says "ten random seeds", but every shipped
Churn evaluation has 5 seeds, and those 5 seeds alone reproduce the printed values.

Configs of the main runs:

- **All four variants:** `n_models = 64`, `d_block = 384`, ReLU, `MuonAdamWPack` with
  `shared_step`, member patience 16, `batch_size = 256`, bf16 AMP, greedy
  `max_ensemble_size = 32`.
- **Online ensemble:** patience 32, `update_type = latest`, current ensemble included
  in the pool. The exception is Offline: `update_type = final`, patience 1e7, current
  ensemble not included in the pool.
- **Embeddings:** the three `-cosine` variants add `CosineEmbeddingsPack` num
  embeddings, and their search space has `n_blocks` in [1, 3] instead of [1, 4].
- **Plain TabPack's unfinished members:** its run stopped when the ensemble ran out of
  patience, with ids 10, 12, 24, 25, 28, 31 and 44 still running.
- **Evaluation configs:** in each variant, the evaluation's fixed configs are the
  sorted unique ids of the main ensemble, e.g. [4, 22, 40, 50, 53] for TabPack. The
  code checks this for every variant (`selected_ids_match_main_ensemble: true`).

These numbers agree with the official-numbers table in `docs/EXPERIMENT.md`
(85.70 / 85.60 / 85.46 / 85.75 ± 0.14; 17.1 s; 4.7-7.0 s per conservative seed).

## Design decisions

- **JSON layout** (`schema_version: 1`):
  - `provenance`: repository, detected clone commit, pinned commit, the README recipe.
  - `variants.<dir>`: `paper_name`, `paper_table14`, `main`, `evaluations`
    (keyed `eval-online-ensembles/greedy` and so on), `evaluation_available`, and
    `conservative`. `conservative` is `{available: false, note}` when a variant has no
    evaluation report.
  - `summary.<dir>`: one flat row per variant.
  - `headline`: the TabPack conservative number with its exact source path.
  - `paper_crosscheck`, `paper_table14`, `other_reports` (Churn reports that fit
    neither pattern; empty for the real clone), and `notes`.
- **Paths and determinism.** All paths are relative to the clone, and the output has
  no absolute paths or timestamps. Re-extraction is therefore deterministic, and the
  parity test compares it byte for byte.
- **Key order.** `extract_churn_reference` returns dicts with recursively sorted keys.
  Any JSON writer then emits the committed key order, including a29's `dump_json`,
  which has no `sort_keys`. NaN and inf become `null`, so the output is strict JSON.
- **Main run semantics.** The report's `n_models` counts finished members. I record
  it next to `n_models_configured`, `n_unfinished` and `unfinished_ids`. The best
  single member is the official `report['best']` (first member with a strictly
  higher val score, in finishing order). When that key is missing, I recompute it the
  same way. `n_val_ties` records val ties.
- **Scalar metrics only.** Ensemble metrics keep only scalars (accuracy, roc-auc,
  cross-entropy, score). The per-class classification-report dicts are dropped.
- **Paper values are hardcoded.** The Table 14 Churn values are constants in the
  module, with their source recorded. They are not in the clone, and they are used
  only for `matches_paper_table14`, which compares after rounding to 4 decimals.
- **Default paths.** `get_reference_dir` ignores an empty, missing or non-directory
  `$TABPACK_REFERENCE_DIR` and falls back to `<repo>/.reference/tabpack`, where
  `<repo>` is the checkout that contains the package. In a worktree that directory
  does not exist, but `tools/dev/py` sets the env var. `load_saved_reference`
  resolves a relative path against the cwd first, then against the repository root.
- **Stdlib only.** The module uses no torch and no peer modules. It calls `git` once
  to read the clone's HEAD, with `GIT_OPTIONAL_LOCKS=0`; the commit is `None` when the
  clone is not a git checkout.

## Tests

`tools/dev/py -m pytest tests/reporting/test_reference.py -q` gives **21 passed**,
including the parity test against the real clone. With
`TABPACK_REFERENCE_DIR=/nonexistent`, run from the worktree, the parity test is
skipped as intended. `ruff check` and `ruff format --check` pass on both owned Python
files.

Coverage:

- **Mini-clone extraction:** main-run fields, ensemble fields, unfinished ids, best
  single member (from `report['best']` and recomputed with ties), member statistics,
  and config highlights including num embeddings.
- **Evaluation:** per-seed fields, mean and std, text, mapping to main-run ids,
  online vs offline kind, and the paper match and mismatch.
- **Edge cases:** a variant without an evaluation, a clone with no evaluation at all
  (`headline` is None), stray and non-Churn reports, NaN metrics becoming null,
  recursive key sort, determinism, a missing or empty `experiments` dir, and the
  `_main` writer format.
- **`get_reference_dir`:** env var set, env var missing or empty, fallback to the
  default, and None.
- **Committed file:** it loads, has a `tabpack` ensemble test accuracy in (0.8, 0.9),
  has the headline "85.75 ± 0.14", the commit matches the pinned one, and it is in
  the canonical format. `load_saved_reference` works from another cwd and raises the
  right errors.
- **Parity:** a fresh extraction from the real clone equals the committed JSON, both
  as parsed data and byte for byte.

## Open issues

- **Paper values are a transcription.** The Table 14 values come from the arXiv HTML
  (v1), retrieved 2026-09-24. They are not in the official clone. If a later arXiv
  version changes the table, update `_PAPER_TABLE14_CHURN`.
- **Paper caption vs shipped seeds.** The caption says ten seeds, but the shipped
  evaluations have 5. Our conservative protocol (5 seeds, per `docs/EXPERIMENT.md`)
  matches the shipped reports, which is the right comparison.
- **Writing the file from the CLI.** a34's `reference` subcommand can write
  `extract_churn_reference(get_reference_dir())` with a29's `dump_json`. The result
  is byte-identical to the committed file (verified against feat/a29-utils), because keys are pre-sorted and the
  settings are the same (indent 2, `ensure_ascii=False`, trailing newline).
